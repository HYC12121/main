# DAS-SentinelAgent 项目功能与验证报告

**项目名称**：DAS-SentinelAgent（安恒星巡）  
**项目定位**：面向网站安全风险评估与敏感信息防泄露的智能巡检系统  
**报告版本**：2026-09  
**当前代码仓库**：<https://github.com/HYC12121/main>

## 1. 项目摘要

DAS-SentinelAgent 是一个可本地部署的网站安全巡检原型。系统在明确授权域名和巡检边界内，完成页面与资源发现、常见漏洞和弱配置检查、暗链/挂马与页面篡改识别、敏感信息检查、证据留存、风险去重定级、基线对比、告警、报告导出和复测。

本版本重点完善了“真实数据闭环”而非演示数据：扫描结果来自目标 HTTP 响应和实际工具输出；连接失败、响应为空或证据不足时，不再伪造安全评分或漏洞结论。外部 Nuclei、Gitleaks、OWASP ZAP 适配器默认关闭，启用后会记录实际版本、退出码、耗时和结果数量。

## 2. 建设目标与范围

### 2.1 已实现目标

- 录入授权域名、目标 URL、最大深度、最大页面数、QPS 和自定义敏感规则。
- 通过异步 BFS 发现页面、表单、URL 参数、静态资源、JS 文件和 API 端点。
- 检测常见 Web 漏洞、敏感路径暴露、CORS 缺陷、反射型 GET 参数 XSS、源码泄露等风险。
- 检测隐藏暗链、恶意外链、挖矿脚本、页面涂鸦和 DOM 异动。
- 对身份证、手机号、银行卡、云凭证、数据库连接串和单位自定义规则进行检查，并对证据脱敏。
- 对结果进行指纹去重、证据复核、严重性分级和修复建议生成。
- 支持定时巡检、历史基线 Diff、告警、任务重跑、问题复测和 HTML/JSON 报告。

### 2.2 当前明确不在范围内

- 恒脑平台运行时兼容性和 AI 动态规划效果尚未验收。
- POST 写入型表单默认不自动提交，避免产生存储型数据或修改业务状态。
- 纯浏览器端 DOM XSS 尚未接入无头浏览器执行验证。
- 外部工具和公网大规模统计评估不纳入本报告指标。

## 3. 系统架构

```text
Web 控制台 / REST API
          │
          ▼
任务模型与授权校验 ── 定时调度器
          │
          ▼
InspectionOrchestrator（任务状态、编排、审计）
          │
          ├─ AssetCrawler：页面、表单、参数、JS、资源发现
          ├─ VulnerabilityDetector：漏洞、配置、参数探针
          ├─ TamperDetector：暗链、挂马、篡改
          ├─ SensitiveInspector：敏感信息与自定义规则
          ├─ RestApiProber / DeepExploitEngine：API 与证据复核
          └─ 可选 Nuclei / Gitleaks / ZAP 适配器
          │
          ▼
证据复核与去重 ── 风险分级 ── 基线 Diff ── 告警/报告
          │
          ▼
SQLite 任务、发现、快照、审计日志
```

插件通过 `BaseScanner` 和 `ScanContext` 连接。当前 `ScanContext` 明确保存 `forms` 和 `url_parameters`，避免资产发现结果在编排阶段丢失。

## 4. 核心功能说明

### 4.1 资产与参数发现

`AssetCrawler` 使用异步 BFS，在授权域名、最大深度、页面数量和 QPS 限制内抓取 HTML/JSON/文本响应，提取：

- 页面链接和资源引用；
- GET 表单及其字段；
- URL 查询参数；
- JS 中的 API 路由；
- robots、sitemap 和 API 文档中的路由；
- 页面注释中的站内路径提示。

所有跳转和后续请求都会再次执行授权域名检查。

### 4.2 漏洞与弱配置探针

内置探针包括：

- 反射型 GET 参数 XSS 的 HTML/属性/脚本上下文分析；
- CORS Origin 反射和凭据配置；
- `.git/HEAD`、`.env`、`backup.sql`、Swagger、Actuator 等敏感路径；
- 源码文件暴露与 SourceMap 泄露；
- SQLi、LFI、SSTI、命令注入、SSRF、BOLA/IDOR 等非破坏性证据探针；
- HTTP TRACE 和其他可验证配置问题。

参数探针使用 URL 结构化编码，保留原有查询参数；单纯回显命令字符串不会再被当成命令执行证据。

### 4.3 防篡改、暗链与挂马

系统离线解析已抓取页面和脚本，识别 `display:none`、负坐标隐藏链接、博彩/恶意外链、挖矿脚本、混淆执行特征和典型页面涂鸦。

### 4.4 敏感信息防泄露

内置身份证校验位、银行卡 Luhn 校验、手机号号段校验、云厂商凭证和数据库连接串规则；通过规则 API 支持单位自定义关键词、正则、样例和风险级别。报告默认只保留必要上下文并脱敏敏感值。

### 4.5 运营闭环

任务状态包含创建、运行、完成、失败和中断；启动/关闭时会处理遗留任务。每次扫描写入页面快照、漏洞指纹和审计日志，支持：

- 新增、修复、保留风险识别；
- 页面 DOM 变化检测；
- Webhook/钉钉告警；
- 问题状态流转和单条复测；
- HTML 报告和 API 查询。

## 5. XSS 问题修复记录

此前真实靶场的 XSS 未检出，根因是：爬虫已经发现 GET 表单 `msg`，但 `VulnerabilityDetector.run()` 只接收了 API 和静态资源元数据，`forms` 与 `url_parameters` 在编排阶段被丢弃，导致参数探针收到空列表。

本版本的修复包括：

1. 在 `ScanContext` 增加 `forms`、`url_parameters` 字段；
2. `AssetCrawler.run()` 将发现结果写入上下文；
3. `VulnerabilityDetector.run()` 将表单、参数和 JS 元数据传入 `scan_all()`；
4. 对参数探针统一使用结构化 URL 编码；
5. POST 表单默认跳过，避免无授权的状态变更。

真实靶场容器过期前，已直接确认其根页面的 `msg` 参数存在未转义回显；当前容器过期后返回 404，无法再次发起复测。代码层和本地靶场回归均已验证修复链路。

## 7. 安全合规设计

- 所有目标必须提供授权域名白名单；
- 默认 QPS、并发、深度、页面数和超时均有限制；
- 禁止携带 URL 中的用户名、密码和令牌；
- 外部工具默认关闭，必须显式加入允许清单；
- 证据不足时标记为疑似或不完整，不伪造漏洞；
- 不自动执行 POST 写入型表单；
- 任务、工具、告警和报告阶段均写入审计日志；
- `.env`、数据库、运行报告等本地数据默认不应提交到代码仓库。

## 8. 部署与使用

### 8.1 本地启动

```powershell
pip install -r requirements.txt
python -m pytest -q
python run.py
```

控制台默认地址：`http://127.0.0.1:8000`。

系统默认是真实目标模式，不会自动启动内置靶场；本地靶场仅在显式设置 `ENABLE_BUILTIN_LAB=true` 时启动。

### 8.2 生产使用建议

正式巡检前应确认书面授权、目标域名/端口、账号权限、扫描时间窗口和 QPS；先以只读 GET/被动模式试运行，再根据业务方批准开启额外主动探针。部署环境应通过环境变量提供告警地址、密钥和数据库配置，不将其写入代码或报告。

## 10. 结论

DAS-SentinelAgent 当前已经具备可部署的本地功能原型，形成了从授权、发现、检测、证据复核、去重定级到告警、报告和复测的完整闭环。最新版本修复了表单参数在编排链路中丢失导致的 XSS 漏检问题，并通过自动化测试和真实靶场实验验证了“真实响应驱动、无虚拟结论”的实现方向。

正式投入生产或参赛演示前，仍应扩大测试样本，补齐浏览器端和 POST 场景，并完成部署环境及授权边界审查。
