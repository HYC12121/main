# 👥 团队三人并发协同与开发手册

## 1. 三人团队明确角色与目录分工

为了避免协作过程中的代码冲突 (Merge Conflicts)，团队 3 位成员严格遵循**“各司其职、各居其位”**的原则：

| 团队角色 | 负责成员 | 独占开发目录 | 核心职责 | 协作边界 |
| :--- | :--- | :--- | :--- | :--- |
| **🎨 前端研发** | 成员 A | `frontend/` | UI 控制台、CSS 主题、任务监控、图表呈现 | 只通过 REST API 交互，绝不修改后端或扫描逻辑 |
| **⚙️ 后端基座** | 成员 B | `backend/` | API 路由、SQLite 存储、任务调度器 (Orchestrator)、APScheduler | 维护微内核基座与任务状态机，不写具体漏扫规则 |
| **🛡️ 安全研发** | 成员 C | `plugins/` | `scanner_core` 与 `scanner_extensions` 各方向插件 | 专心编写/升级扫描算法，只与 `ScanContext` 通信 |

---

## 2. 安全工程师新增插件五步法 (Zero Conflict Workflow)

成员 C 在需要增加新检测能力（如端口扫描、API 模糊测试或新漏洞探针）时，遵循以下标准步骤：

```mermaid
graph LR
    Step1[1. 选择目标子目录] --> Step2[2. 继承 BaseScanner]
    Step2 --> Step3[3. 实现 async run 方法]
    Step3 --> Step4[4. 从 context 读写数据]
    Step4 --> Step5[5. pytest 单测验证]
```

### 标准代码模板：

```python
# 示例路径：plugins/scanner_extensions/api_fuzzer/graphql_prober.py
import logging
from plugins.core.base import BaseScanner, ScanContext

logger = logging.getLogger("das_sentinel.graphql_prober")

class GraphQLProber(BaseScanner):
    """GraphQL 接口安全探针扩展插件"""
    
    def __init__(self, *args, **kwargs):
        super().__init__()

    async def run(self, context: ScanContext) -> None:
        logger.info(f"[GraphQLProber] 开始探测目标: {context.target_url}")
        
        # 1. 从数据总线消费前置数据
        endpoints = context.api_endpoints
        
        # 2. 执行检测逻辑 (非破坏性)
        findings = []
        for ep in endpoints:
            if "graphql" in ep.lower():
                findings.append({
                    "id": f"graphql-{context.task_id}",
                    "category": "VULN",
                    "level": "LOW",
                    "title": f"发现暴露的 GraphQL 端点: {ep}",
                    "target": ep,
                    "evidence": "GraphQL endpoint detected",
                    "remediation": "若非必须公开，建议配置网关访问控制并关闭 Introspection。"
                })

        # 3. 将结果灌回数据总线
        if findings:
            context.add_findings(findings)
```

> [!IMPORTANT]
> **无需改动后端代码**！
> 编写完成后，`plugins/core/registry.py` 的递归自动发现器会在系统启动时自动装载该插件并纳入调度闭环！

## 3. 防代码冲突 (Merge Conflicts) 黄金准则

1. **绝对禁止跨目录硬编码 Import**：
   - 严禁在 `plugins/` 内 `import backend.app.agent.orchestrator`；
   - 严禁在 `backend/` 内硬编码 `from plugins.scanner_extensions.xxx import MyScanner`（统一使用 `scanner_registry`）。
2. **测试与辅助脚本收纳**：
   - 所有单测放入 `tests/test_*.py`；
   - 所有的临时运行脚本放入 `scripts/`，绝不在项目根目录随手丢 `.py` 文件。
3. **提交前自检**：
   - 在本地运行 `python -m pytest`，确保 21 个自动化测试用例全部绿灯通过。
